# 拾影：媒体探测与最高画质保障技术白皮书
> 版本：v1.0.0 · 核心技术内幕与质量保障体系

---

## 1. 核心定义：“平台最高可用”与“不压缩”

在多媒体资源归档领域，许多工具受限于解析库的默认规则，往往将带有“2K/4K”标签的派生降档流或 720p 占位流当成最高质量。拾影系统坚持**“零二次重编码、无损封装合并、实测物理参数优选”**的三大铁律：

1. **不二次压缩 (No Re-encoding)**：直接逐字节落盘平台分发的原始多媒体字节，或仅通过 FFmpeg 执行 Copy 封装（Remux），绝不使用 CPU/GPU 对音视频帧进行二次有损量化。
2. **拒绝标签欺骗 (Verify, Don't Trust)**：不相信网页端下发的虚假清晰度标签，所有候选流必须在下载前或下载后通过 FFprobe 进行真实的物理像素、实际码率、真实时长校验。
3. **阶梯式降级探测 (Fallback Ladder)**：优先获取平台可提供的天花板画质（如 4K/8K、原图 HEIC），若受风控或会话限制无法获取，按严密阶梯选择次优无损流，绝不静默保存低质劣质缩略图。

## 2. 各平台媒体探测与链路防护实现规范

### 2.1 抖音与抖音精选 (Douyin & Selected Douyin)
- **双源交错探测**：
  - 将作者作品接口中最高像素的 `direct rendition` 与同一媒体 ID 的官方 `default/amemv` 原始档作为两条权威来源。
  - 交错尝试两个固定官方播放入口的 `line=0` 与 `line=1` 四条同档路由，探测为同一完整媒体指纹的镜像合并为同档候选。
- **逐跳严格安全过滤**：
  - 关闭自动重定向，逐跳检查 HTTP `Location` 头部。
  - 下一跳只有落在明确白名单内的字节跳动官方 CDN 域名后缀（如 `douyinvod.com`），且使用无账号信息、标准端口的 HTTPS 地址时才真正发出请求。
  - 拦截任何私网 IP（`127.0.0.1`、`192.168.x.x`）或异常端口。
- **MP4 前缀与时长校验**：
  - 完整传输后核对精确字节数、前 256 KiB SHA-256 指纹、视频/音频编码（codec）、实际分辨率与严格时长容差，全部一致才原子替换目标文件。
- **图文与 Live Photo 规范**：
  - 图文只接受作品数据中最高像素的 `images[].url_list`，拒绝使用带有 `q75` 压缩的派生流。
  - Live Photo 优先提取最高质量动态 MP4，实况静态照片与同名动态视频严格成对保存，绝不拆散。

### 2.2 小红书 (Xiaohongshu)
- **Direct CDN 与原视频 Key 优先**：
  - 视频优先使用 `originVideoKey`，再从 `media.stream` 与 `mediaV2` 中按真实像素、码率与文件体积选流。
  - 图片优先重建 direct CDN 原始地址，网页端中的 DFT/PRV 预览图仅作为兜底回退。
- **Live Photo 独立像素计算**：
  - 实况照片的静态照片（HEIC/JPG）与动态流（MP4）是独立媒体：仅使用动态流本身的物理宽高计算尺寸，杜绝把照片像素错误套给动态视频。

### 2.3 哔哩哔哩与 YouTube
- **音视频分离流无损 Remux**：
  - 采用 `bestvideo*+bestaudio/best` 策略，独立抽取最高码率的无损视频轨与最高音质的音频轨。
  - 仅调度 FFmpeg 执行 `-c copy` 转封装合并，输出完整 MP4/MKV，画面质量零损失。
- **多 P 选集与播单展开**：
  - 针对 `?p=1,2` 选集、合集播单，自动维护索引前缀（如 `001-标题.mp4`），保持专辑连续性。

### 2.4 微信视频号 (WeChat Channels)
- **ISAAC64 动态解密管道**：
  - 针对闭环私有流媒体，通过腾讯元宝会话桥接获取加密流。
  - 下载首部 128KB（131,072 字节）数据，基于 ISAAC64 密钥流实时执行 XOR 还原，解密后由 FFprobe 复核视频编码完整性。
- **硬件加密存储 (DPAPI)**：
  - 本地会话凭证通过 Windows DPAPI (`CryptProtectData`) 加密存入本地文件，严禁明文入库。

## 3. 防重冲突与原子落盘机制 (`file_publish.py`)

1. **首尾快速哈希比对**：
   - 体积 ≤ 1MB：逐字节全量哈希对比；
   - 体积 > 1MB：对比首尾各 64KB（65,536 字节）块，耗时小于 5ms。
2. **相同内容智能复用**：
   - 目标路径存在相同文件时，立即复用已有路径并清理临时 `.part` 分段文件，实现秒传。
3. **不同内容重名避让**：
   - 若哈希不同，自动以 `{Stem} (2){ext}` 格式递增重命名，绝不覆盖已有旧文件。
4. **成对独占锁**：
   - Live Photo 在落盘时加全局 `_PAIR_NAME_LOCK`，确保图片与视频同名成对，绝不出现序号错位。
