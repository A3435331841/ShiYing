## 0. 本复盘的事实基础与「不假设」声明

### 0.1 理念基线（可核查，非原始资料）

项目内**不存在** PRD、需求文档、原型说明、UI 规范或竞品参考。经维护者确认，本轮以以下三份可核查材料作为「最初设计初衷」的替代基线，并明确标注为**推断而非原始记录**：

| 基线来源 | 原文要点 | 推断出的设计约束 |
|---|---|---|
| `README.md:22-26` 四条原则 | 不重编码 / 自动探测最高可用画质 / 结构化归档 / 单机完全受控 | 画质必须可见可查；归档结果必须产品内可浏览；隐私与本地性必须可见 |
| `NOTICE.md:13-15` 产品出身 | 开源下载底座 + 中文主页 + 桌面壳 | 定位是「本机工具」而非 SaaS；不做账户系统、不做云端能力 |
| `design/主页参考.png` | 真实缩略图为识别主体、Hero 文案「把喜欢的内容，留在本机」、按收藏/画质组织 | 媒体身份 > 任务后台身份；参考图中的「收藏链接」「窗口装饰」**不自动视为开发要求** |

目标用户口径：`docs/archive/拾影全项目审查与改进建议-2026-11-10.md:9` ——「一个人长期使用、更新和维护这个产品，尽量少配置、少等待、少重复劳动，出现问题后能够自行恢复」。这是单人本机日常自用工具。

### 0.2 「通用 AI 模板感」的重新定义（对需求的修正）

原需求描述为「当前浓重的通用 AI 模板感」。经核对当前源码与 `design/主页参考.png`、以及 `审计产物/UI设计审计-2026-11-10/UI审美与设计审计报告.md`，**字面上不成立**：

- `home.css` 使用克制蓝灰工具风（`--brand:#2f66f5`），无渐变紫、无玻璃拟态；全仓唯一 `backdrop-filter` 是 `dialog::backdrop`（标准弹窗遮罩）。
- 官方审计报告 `:8` 明确「最需要的不是再加装饰」，`:158` 明确「无需改成另一套流行配色，也无需加渐变大卡片或动效来制造高级感」。
- 换配色会推倒刚实测达标的对比度基线（发布清单 `:49`：暗色 4.50 / 浅色 4.84，WCAG AA）。

**真实问题**是审计 `:162-166` 点名的「**通用任务后台感**」：所有任务固定输出同一个 film 占位符、真实封面未成为识别主体、平台色/状态色/进度色/错误色四色竞争。

因此本轮目标修正为：**保留已达标的蓝灰基底与主题 token，建立「本地影像档案」的产品身份**，而不是「换配色去 AI 感」。视觉方向经维护者确认选择「影像档案 · 保留蓝灰」。

### 0.3 历史档案的时态警示

`审计产物/UI设计审计-2026-11-10/` 的 28 张截图冻结于 v0.3.0（service build `a4f6728a445c`）。当前源码已包含：官方平台图标替换、断点重划（520/760/1040/1220）、暗色对比度修复、选集全选/全不选、「下载缓存」文案、`paused:"已暂停"` 字典。**旧截图不可直接作为现状缺陷清单**。

## 4. 信息架构与导航（重设计）

### 4.1 从「按状态分页」到「按意图分层」

```
拾影
├── 收集  Collect      粘贴 → 识别 → 选范围 → 确认 → 入队
├── 进度  Progress     活动队列（进行中 / 排队 / 暂停 / 需处理）+ 状态机
├── 资料库 Archive     已归档媒体：缩略图网格 / 筛选 / 打开 / 移除记录
└── 系统  System       设置（常规 / 登录态 / 存储）· 环境 · 帮助 · 退出
```

依据：现有「首页 / 下载任务 / 已完成」是按任务状态切分，但用户意图是「添加 → 看进度 → 找文件」。「已完成」当前是记录列表，与「归档」承诺错位（A2）。

### 4.2 导航规范

| 端 | 形态 | 规则 |
|---|---|---|
| 桌面 ≥1040px | 左侧固定侧栏 240px | 三主项 + 底部系统区；顶部为上下文标题 + 全局状态（连接 / 主题 / 帮助） |
| 平板 760–1040px | 图标侧栏 76px | 保留 `aria-label` 与 `title`，不靠颜色区分状态 |
| 移动 <760px | **底部 Tab**（收集 / 进度 / 资料库 / 设置） | 不占用内容宽度；任务行改双列；添加区可折叠 |

依据：`width-375-light.png` 实测窄屏侧栏把标题挤成两字、操作按钮折行。

### 4.3 组件层级

```
页面 Page
└── 区 Section（收集 / 活动 / 已归档）
    └── 卡 Card（输入框 / 任务行 / 资料卡）
        └── 三层信息
            L1 作品识别：封面 + 标题
            L2 元信息：作者 · 日期 · 平台 · 规格 · 文件数
            L3 状态与动作：单一主操作 + 更多菜单（详情/重试/移除）
```

任务行固定高度区间，动作区不再随状态在 31/61px 间跳动（B5）。

## 5. 视觉语言规范（影像档案 · 保留蓝灰）

### 5.1 原则

1. **不换配色**：沿用 `home.css` 已实测达标的 `--brand / --ink / --line / --surface` token 与深浅双主题。
2. **用「档案语义」建立身份，而非装饰**：日期刻印式元信息、帧线代替彩色左条、等宽数字承载大小/速度/进度、真实封面成为主识别。
3. **颜色分工**：平台色只在 8px 标记出现；状态色只表达任务状态；进度用中性色 + 品牌色；错误仅在错误行增强。
4. **一张图一个焦点**：缺省封面分视频 / 图文 / 实况三类，不再统一 film 符号。

### 5.2 保留资产（有溯源 / 合规约束，禁止重绘改色）

- `app/static/platform-icons/*` 7 个官方平台图标 —— `platform-icons/README.md:17` 明确「原始响应字节不重绘、不裁剪、不改色」，`sources.json` 记录 SHA-256。
- `app/static/brand.svg` 蓝色影片型标志 —— 审计 `:187` 判定方向合理。
- 全套 `design tokens` 与 `html[data-theme="dark"]` 覆盖。

### 5.3 新增资产（本轮 AI 生成，统一 4:3 1200×900）

| 文件 | 用途 | 约束 |
|---|---|---|
| `media/cover-video.png` | 视频类缺省封面 | 无文字入画、蓝灰档案质感、留白、单一焦点 |

### 5.4 状态矩阵（UI 必须区分，不得混用）

| 状态 | 触发 | 文案方向 | 主操作 |
|---|---|---|---|
| `loading` | 首屏读取 | 「正在读取本机任务…」 | 无（骨架） |
