## 视频号免手动 Cookie 调研

- https://github.com/QinGeneral/wx-downloader 描述了独立浏览器完成一次元宝登录并自动保存凭据的方案：用户无须手工复制 Cookie，但仍有登录态；仓库声明暂不支持直播、图集，其许可证为 MIT + Commons Clause，集成前须评估条款。未在本机登录或验证下载。
- https://github.com/joeseesun/qiaomu-wx-video 描述第三方在线解析及使用已登录微信客户端的本地捕获。在线方案将分享链接提交第三方；本地捕获可能需要根证书和系统代理，Windows 证据不足。两者不是已验证的纯匿名本地解析。
- https://github.com/ltaoo/wx_channels_download/issues/465 报告过在线解析返回 401，不能依赖其长期有效。

结论：目前未找到经本机验证、无需登录且稳定覆盖视频号各类作品的纯本地方案。下一步可研究在拾影中提供独立浏览器扫码登录元宝、自动获取本地登录态的方案，并实测普通视频和解密流；这仍非免登录。账号登录、根证书和代理变更均不得静默执行。

## 微信视频号“免登录下载”技术逆向与调研结论

针对用户提出的“研究视频号免登录下载、看看有没有方法绕过登录”的课题，我们对视频号分享落地页的前端代码与底层网络协议进行了系统性逆向分析，明确了其安全防御机制与技术边界：

### 1. 核心链路与防盗链架构剖析
视频号公开分享短链（如 `https://weixin.qq.com/sph/A7WJC6T1J8`）在 302 重定向到 `channels.weixin.qq.com/finder-preview/pages/sph?id=...` 后的底层行为如下：
1. **首屏接口 `get_feed_info`**：
   - 无登录态请求：通过 `POST /finder-preview/api/feed/get_feed_info`（入参仅带 `shortUri`，`generalToken` 为空），服务端会返回作者信息、标题（`description`）、互动点赞数、封面图（`coverUrl`）以及临时生成的 `dynamicExportId`（形如 `export/UzFfBgAA...`）。
   - **关键防线**：此未鉴权接口在返回的 `feedInfo` 中**完全不包含视频媒体流字段**（`videoUrl`、`h264VideoInfo`、`h265VideoInfo` 均为空），前端页面呈现“请扫码前往微信观看完整视频”的 QR 码遮罩。
2. **次级接口与内嵌 Bridge 拦截**：
   - 前端代码逆向表明，一旦页面尝试调用 `getFeedDetail` 或带 `exportId` 获取媒体流，会检测当前客户端环境。
   - 若通过普通浏览器访问，服务端对未经授权的 `exportId` 直接返回 `errMsg: { type: 2, title: "内容暂时无法浏览" }`。
   - 若通过模拟微信客户端协议访问，底层通过 `ExtTransferService` 路由调用微信客户端内置注入的 `WeixinJSBridge.invoke("finderH5Auth")` 与 `/cgi-bin/micromsg-bin/` 原生通道。该通道直接由微信客户端核心进行登录态绑定与请求签名计算。
3. **媒体流二进制加密 (ISAAC64)**：
   - 即便在拥有有效凭据后获取到腾讯 CDN 直链（`finder.video.qq.com/.../stodownload`），微信视频号对视频文件的前 128KB（131072 字节）进行了基于 ISAAC64 算法的流密码异或加密，且每次请求下发的解密密匙 `decode_key` 与 `url_token` 都是动态绑定的，必须由客户端配合解密才能正常播放。

### 2. 业界开源方案与“免登录”的真实情况
目前 GitHub 上所有主流视频号下载方案均无法做到真正意义上的“零账号匿名爬取”：
- **方案 A（腾讯元宝会话桥接，如 `wx_channels_download`、`wx-downloader`、`WechatVideoDL`）**：
  - 利用腾讯元宝官方接入的微信生态接口（`yuanbao.tencent.com/api/weixin/get_parse_result`）来换取合法播放凭证 `playable_url`（含 `token` 与 `eid`），进而拉取到明文或可解密的视频流。
  - **前提条件**：必须依赖腾讯元宝的有效登录会话（Cookie / Token）。虽然可以通过内置浏览器提供扫码界面实现“免手动复制 Cookie”，但仍然必须完成一次微信扫码登录授权。
- **方案 B（微信桌面端代理 / 流量抓包 / Hook，如 `res-downloader`、`wx_channels` 本地捕获模式）**：
  - 在本机安装根证书并劫持系统网络代理，当用户在 PC 微信客户端内点击播放视频号视频时，抓取微信内部已鉴权并传输的真实媒体流及密钥。
  - **前提条件**：必须运行已登录的微信客户端，且需要修改系统网络和证书信任。
- **方案 C（第三方商业在线解析 API）**：
  - 第三方搭建服务端集群维护大量微信/元宝账号池代为请求，对外暴露无鉴权 API。
  - **风险与局限**：稳定性极差（极易因为账号风控而大面积返回 401/403），且存在隐私泄露隐患，不属于独立的本地免登录解决方案。

### 3. 结论与工程建议
- **结论**：微信视频号不存在官方公开的纯匿名/免登录视频直链获取途径。在纯公开 Web 端访问时，服务端在架构上就物理隔离了音视频流下发，必须具备合法会话上下文（腾讯元宝 Session 或微信客户端本地会话）才能获取。
- **可行的最佳无感化方案**：在拾影中集成轻量化的独立内置浏览器或元宝扫码弹窗（类似 `wx-downloader` 的做法），让用户只需在软件内扫一次码，程序自动提取并加密存储会话凭据，后续粘贴任何分享链接即可直接全自动静默解析与下载，彻底免去手动去浏览器 F12 抓包复制 Cookie 的繁琐操作。
