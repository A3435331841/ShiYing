## 3. 非源码临时目录的治理与清理规则

### 3.1 审计产物 (`审计产物/`)
- **现状**：包含 48 个 PNG 截图与 MD 评估，属于 2026-11-10 阶段性 UI 设计审计的快照。
- **治理决定**：将关键总结归入 `docs/archive/UI设计审计-2026-11-10/`，多余的临时无损截图从仓库移除，避免随 Git 仓库体积持续膨胀。

### 3.2 自动化测试产物 (`artifacts/`)
- **现状**：包含 Playwright 浏览器测试运行日志与临时状态。
- **治理决定**：该目录属于运行态产物，确认已加入 `.gitignore`，可直接清空其内部内容。

### 3.3 规范模板库 (`docs/templates/`) 的落地与日常流转规范
为了保证今后“每天的缺陷漏洞记录”、“修复记录”、“功能特性记录”整齐划一，已确立并生效以下四大标准模板体系：

1. **缺陷追踪流转**：
   - 触发时机：凡是线上出现错误码、测试用例红灯、或安全审计发现隐患时；
   - 使用模板：`docs/templates/BUG_TRACKING_TEMPLATE.md`；
   - 归档路径：`docs/records/bugs/BUG-{YYYYMMDD}-{平台}-{序号}.md`。
2. **修复复盘流转**：
   - 触发时机：提交修复 Commit 前，记录问题诱因、修改 diff 及回归测试用例；
   - 使用模板：`docs/templates/BUGFIX_RECORD_TEMPLATE.md`；
   - 归档路径：`docs/records/fixes/FIX-{YYYYMMDD}-{轮次}.md`。
3. **新功能/新平台接入流转**：
   - 触发时机：新增平台（如 YouTube、TikTok）或重大重构（如抖音精选拆分）；
   - 使用模板：`docs/templates/FEATURE_RECORD_TEMPLATE.md`；
   - 归档路径：`docs/records/features/FEAT-{YYYYMMDD}-{模块}.md`。
4. **日常研发推进与质量同步**：
   - 触发时机：每日工作交接、测试回归结论总结；
   - 使用模板：`docs/templates/DAILY_PROGRESS_TEMPLATE.md`；
   - 归档路径：`docs/records/progress/PROGRESS-{YYYYMMDD}.md`。

## 4. 目录治理演进执行操作指南

为保证治理动作平稳、无破坏性，建议按如下三个安全批次分步实施：

### 阶段一：纯文档与标准模板收敛（零代码风险）
1. 在 `docs/` 下建立清晰子目录体系：
   - `docs/guides/`（用户指南）
   - `docs/specs/`（架构与接口规范，含 279 项 Excel 矩阵）
   - `docs/templates/`（四大日常工程模板，已落地）
   - `docs/records/`（未来日常缺陷、修复、特性日志的归档目录）
   - `docs/archive/`（历史交接备忘、旧轮次推进记录）
2. 移动根目录文档到对应 `docs/` 子目录，建立顶层索引跳转。

### 阶段二：运维与启动脚本归拢（保持 Windows 核心入口不动）
1. 建立 `scripts/dev/` 与 `scripts/unix/`；
2. 将 `start.sh`、`stop.sh`、`start.command`、`stop.command` 移入 `scripts/unix/`；
3. 将非核心的英文 `start.bat`、`stop.bat`、`安装依赖.bat` 移入 `scripts/dev/`；
4. 根目录仅保留 **`启动拾影.bat`** 与 **`停止拾影.bat`**，实现用户体验的极致清爽。

### 阶段三：核心平台 SPI 与抖音精选物理拆分
1. 将 `app/platforms.py` 内部耦合逻辑拆分为统一 SPI；
2. 在 `app/models.py` 中将 `Platform.SELECTED_DOUYIN` 正式固化；
3. 全面执行 1900+ 单元测试回归，确保 100% 绿色无损。
