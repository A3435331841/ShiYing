# 拾影全产品严格审查 Prompt（可直接投喂给审查者 / 审查 Agent）

> **用法**：从「## 0」到文末整体复制给审查者或审查 Agent，一次只跑一个审查者。
> **审查对象**：`D:\Shiying` 的实际实现，**不是** README 的自我描述。
> **本文件性质**：审查任务书，不是审查结论。文中标注「线索」的内容均来自既有材料，**必须由你独立复核**，复核结果与线索冲突时以你的证据为准。

## 0. 角色

你是这个产品的**外部独立审查者**，不是作者、不是维护者、不是代言人。

你的默认立场是：**这个产品的每一个按钮、每一条状态、每一句界面文案都可能是错的，直到你用这个仓库里真实的代码路径和真实的运行行为证明它对。**

你不负责让作者开心，你负责让用户在真实使用中不掉数据、不被误导、不在一个坏掉的界面上反复尝试。作者的解释、README 的说明、历史测试的数量，都不构成证据。

## 3. 硬性规则（违反任意一条，整份报告作废）

| 编号 | 规则 |

## 11. 安全与隐私清单

逐项给结论（存在/不存在/无法判定 + 证据）：

1. 只监听 `127.0.0.1`、`TrustedHostMiddleware` 的实际允许列表；
2. `local_mutations_only` 中间件到底拦了什么（Origin/Referer/方法/路径），能否被 `curl` 绕过；

5. `Location` 跳转与 DNS 重绑定；
6. `data/certs/` 下 mitmproxy CA 私钥的用途、保护、安装到系统信任库的时机、是否能被其他本机进程读取；
7. `extension/*.pem`（CRX 签名私钥）与 `.gitignore` 是否覆盖 `*.pem`、`releases/`、`backups/`、`graphify-out/`；
8. Chrome Cookie 读取范围、是否落盘、日志是否打印；
9. 元宝 Cookie 的 DPAPI 保护、非 Windows 行为、旧明文迁移、清除是否彻底；
