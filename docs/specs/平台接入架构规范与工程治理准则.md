# 拾影（Shiying）多媒体平台接入架构规范与工程治理准则
> 版本：v1.0.0 · 2026 架构基准规范  
> 适用范围：拾影全系统内核、平台接入扩展、目录工程治理与全生命周期交付

---

## 1. 架构愿景与设计哲学

拾影是一个专注于**“本地化、高保真、去中心化”**的多媒体资源采集与归档系统。随着系统从最初支持国内短视频（抖音、快手、小红书），逐步扩展到长视频/专栏（B站）、私有流媒体（微信视频号），以及国际化主流平台（YouTube），未来的扩展边界还将涵盖 TikTok、Instagram、X (Twitter) 等全球多媒体平台。

为了防止平台特化代码腐化核心调度逻辑，必须确立以下核心设计原则：

1. **开放封闭原则 (Open-Closed Principle, OCP)**：核心下载引擎、调度器和主进程不感知具体平台的业务逆向细节。新增一个平台只需遵循 SPI 规范新增一个插件包，禁止侵入核心状态机。
2. **单一平台物理隔离 (Strict Platform Encapsulation)**：每个平台的 URL 正则、鉴权签名、媒体探测、特化解密、反风控策略必须封装在独立的命名空间内，杜绝跨平台逻辑耦合。
3. **分层清晰与契约驱动 (Contract-Driven Layering)**：严格区分“表现层 (UI/Web)”、“服务层 (API/Manager)”、“领域层 (Platforms SPI)”、“执行层 (Engine Pipeline)”与“基础设施层 (System/OS/Security)”。
4. **全球化视野与前瞻兼容 (Future-Proof & Global-Ready)**：兼顾国内平台的复杂反爬（签名、滑块、风控）与海外平台的合规解密挑战（如 YouTube n-sig、Deno 运行沙箱、多音轨多语言字幕）。

## 2. 统一平台抽象契约 (Platform SPI Specification)

每一个多媒体平台在接入拾影时，必须且只能实现统一的 `PlatformProvider` 抽象接口契约。平台代码必须作为一个独立的 Python Package 位于 `app/platforms/<platform_key>/` 目录下。

```
app/platforms/
├── base.py                     # 全平台统一抽象基类 (PlatformProvider ABC)
├── douyin/                     # 抖音主站 (竖屏/图文/实况)
├── selected_douyin/            # 抖音精选 (中长视频/横屏/知识合集)
├── xiaohongshu/                # 小红书 (图文/视频/实况/画质回退)
├── kuaishou/                   # 快手 (短视频/横版图集/竖版16切片)
├── bilibili/                   # 哔哩哔哩 (单P/多P选集/播单/专栏动态)
├── youtube/                    # YouTube (常规/Shorts/频道/列表/Deno解密)
├── wechat/                     # 微信视频号 (元宝Session/ISAAC64解密/DPAPI)
└── (未来扩展预留插槽)
    ├── tiktok/                 # TikTok 全球短视频
    ├── instagram/              # Instagram 快拍/Reels/帖子
    └── twitter_x/              # X (Twitter) 动态推文与高清流
```

### 2.1 平台提供者六大标准生命周期接口 (Standard Lifecycle Hooks)

每个平台的 `provider.py` 必须实现以下六大标准阶段：

```python
class PlatformProvider(ABC):
    platform: Platform  # 强类型平台枚举标识

    # 阶段 1：URL 识别、归一化与类型判定
    @abstractmethod
    def identify(self, url: str) -> UrlInfo:
        """匹配自身 URL 规范，完成短链还原、防串号参数提取，返回标准化 UrlInfo。"""

    # 阶段 2：会话鉴权与凭证策略
    @abstractmethod
    def prepare_session(self, context: SessionContext) -> SessionAuth:
        """决定使用无痕匿名会话、系统 Chrome Cookie，还是平台专属硬件加密凭证。"""

    # 阶段 3：元数据发现与合集展开 (Discovery)
    @abstractmethod
    def discover(self, target: UrlInfo, auth: SessionAuth) -> DiscoveryResult:
        """解析单作品、多P选集、合集播放列表或作者主页，产出标准的 DownloadItem 集合。"""

    # 阶段 4：媒体流探测与最高画质优选 (Probe & Quality Floor)
    @abstractmethod
    def probe_streams(self, item: DownloadItem, auth: SessionAuth) -> list[MediaStream]:
        """执行多源探测 (如双源、Line0/1)、码率与真实分辨率实测，按画质从高到低排序。"""

    # 阶段 5：特殊形态解密、挑战应对与媒体封装 (Crypto & Remux)
    @abstractmethod
    def process_stream(self, stream: MediaStream, raw_data: bytes) -> ProcessedMedia:
        """处理特定平台解密 (如 ISAAC64)、音视频分离流合成 (FFmpeg Remux)、JS挑战执行 (Deno)。"""

    # 阶段 6：归档命名与实况成对规则 (Naming & Packaging)
    @abstractmethod
    def resolve_output_path(self, item: DownloadItem, root_dir: Path) -> Path:
        """应用平台归档规范，生成平台/作者层级路径，处理实况照片成对配准与超长截断。"""
```

## 5. 跨平台兼容、系统安全与沙箱规范

### 5.1 外部运行时依赖与沙箱矩阵
| 依赖组件 | 所属领域 | 职责说明 | 缺失时系统行为与降级策略 |
| :--- | :--- | :--- | :--- |
| **FFmpeg** | 媒体合成 | B站音视频分离流混流、全格式格式转封装 | 拦截下载并告警，禁止生成分离半成品 |
| **FFprobe** | 质量实测 | 探测媒体流真实物理码率、宽高、时长，校验坏道 | 无法校验真实画质，降级提示用户安装 |
| **Google Chrome** | 交互逆向 | 快手被动监听、小红书主页滚动、滑块风控唤起 | 快手及部分高级主页功能不可用，提示安装 |
| **Playwright** | 自动化驱动 | 抖音签名兜底执行、视频号扫码登录小窗 | 抖音自动降级至远程/纯算法签名；视频号提示扩展导入 |
| **Deno Runtime** | JS挑战沙箱 | YouTube n-sig 解密挑战执行，轻量沙箱隔离 | 无法解密 YouTube 高清流，自动降级至基础格式 |

### 5.2 安全防护与隐私红线
1. **SSRF 严格防御**：所有平台重定向链接必须经过逐跳校验，禁止跳转至私网 IP (`127.0.0.1`, `192.168.x.x`, `10.x.x.x`) 或非标端口。
2. **凭据硬件隔离存储**：
   - Windows：强制使用 `CryptProtectData` (DPAPI) 绑定当前用户主密钥加密，严禁明文入库；
   - macOS / Linux：通过系统 Keychain 或 Secret Service 存储凭证。
3. **零敏感信息泄露**：
   - 所有的日志、异常堆栈、前端返回 JSON 中，必须自动执行正则脱敏，严禁打印 Cookie 明文、xsec_token 等鉴权密钥。
4. **媒体打开防投毒**：
   - 桌面打开文件必须严格匹配 `OPENABLE_MEDIA_SUFFIXES` 23 种多媒体白名单，严禁直接执行 `.exe`, `.bat`, `.vbs`, `.lnk` 等任何可执行文件。

## 6. 文件落盘归档与防重冲突算法规范

### 6.1 归档目录结构标准
所有平台下载的最终资产必须统一采用两级目录归档，并严格遵循以下模板：
```
downloads/
└── {Platform_DisplayName}/                 # 平台一级目录 (如 Douyin, Selected-Douyin, YouTube)
    └── {Author_Name}/                      # 作者二级目录 (非法字符清洗，空回退为 Unknown-Author)
        ├── {YYYY-MM-DD}-{Title} [{ID}].ext                      # 单作品文件
        └── {YYYY-MM-DD}-{Album_Title} [{Album_ID}]/             # 多P/合集专属子目录
            ├── {Index:03d}-{Title} [{ID}].ext                   # 分集按三位序号排列
            ├── {Index:03d}.ext                                  # 图集按三位紧凑序号排列
            ├── {Stem}.heic                                      # 实况照片主静态图
            └── {Stem}.mp4                                       # 实况照片同名动态视频
```

### 6.2 极端重名冲突与复用算法 (`publish_or_reuse_identical`)
1. **首尾快速哈希比对**：
   - 文件大小不等或为 0 ➔ 判定为不同文件；
   - 体积 ≤ 1MB ➔ 逐字节全量比对；
   - 体积 > 1MB ➔ 对比首尾各 64KB (65536 字节) 数据块，耗时 < 5ms。
2. **智能复用**：若目标目录下已有完全相同内容的文件，立即删除临时分段文件并复用已有路径，达成秒级完成。
3. **重名避让递增**：若内容不同，循环查找 `{Stem} (2){ext}` 直至 10001，绝不覆盖用户已有旧文件。
4. **实况照片基名同步独占锁**：加全局 `_PAIR_NAME_LOCK`，确保图片与视频同名成对，绝不出现序号错位。

## 7. 演进路线图与迁移纪律

```
重构演进四步走路线图：
[第一步：根目录极简瘦身] ➔ [第二步：抖音与精选平台独立] ➔ [第三步：app/ 内部平台 SPI 分包] ➔ [第四步：全量测试 100% 验收]
```

1. **第一步（根目录瘦身）**：清理冗余脚本，保留 `启动拾影.bat` / `停止拾影.bat`，散落文档归入 `docs/`，过程产物归入 `build/`。
2. **第二步（平台独立模型）**：在 `app/models.py` 确立 `Platform.SELECTED_DOUYIN`，实现抖音精选从识别、过滤到存储目录的完全独立。
3. **第三步（平台 SPI 封装）**：将平铺的爬虫文件迁移至 `app/platforms/<platform>/`，收拢通用流处理至 `app/engine/`。
4. **第四步（全面回归）**：保持所有单元测试导入兼容，全量回归验证 1900+ 项测试用例，确保功能 100% 绿色无损。
