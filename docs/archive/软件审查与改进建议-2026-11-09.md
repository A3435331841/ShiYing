# 拾影软件审查与改进建议

> 📌 **【历史归档文档 · 适用版本：v0.1.0 (2026-11-09) · 仅供历史审查追溯】**  
> 本文中所列问题在 v0.2.0 与 v0.3.0 中已全数完成对应重构与修复。最新现状请参阅 [完整修复推进记录.md](../../完整修复推进记录.md)。

审查日期：2026-11-09。依据当前源代码、界面文本、运行服务健康检查和已有平台实测报告。这里的代码问题是静态审查结论；除明确注明的历史样本外，本次没有完成新的各平台实站下载验收。

## 最优先处理

1. **视频号可能下载错作品。** `app/wechat.py:182` 从全局捕获队列取第一条记录，没有用用户提交的链接或作品 ID 进行匹配；多个任务或播放其他视频时，可能把别的视频记到当前任务。建议绑定作品身份，无法确认时要求用户选择或拒绝完成，并覆盖并发和旧队列场景。
2. **视频号代理和证书的生命周期不可靠。** `app/wechat.py:169` 忽略证书安装结果，代理线程启动后未确认监听成功就改系统代理；取消、超时和失败后未立即恢复，仅在服务正常关闭时清理；异常退出后可能遗留。证书删除使用名称而非精确指纹，也未记录是否由本软件安装（`app/wechat_cert.py:29`）。建议明确提示、检查每步结果、保存完整原状态与本软件证书指纹，任务结束立即恢复，并提供异常退出后的恢复机制。
3. **视频号代理可能影响微信播放及其他 HTTPS 流量。** `app/wechat_proxy.py:140` 设置了 `ssl_insecure=True`；`response` 中会修改送回客户端的视频数据（第 80–91 行），而解密器没有传入分片起始偏移，非零偏移分片的处理是否正确尚未证明。建议只监听目标流量、验证上游证书，避免改写微信响应，并对分段、并发、密钥变化进行真实客户端验证。
4. **视频号界面缺少关键状态。** 后端使用 `capturing`，但 `app/static/home.js:7` 的状态标签及活跃状态列表均不包含它；这会让等待播放的任务显示状态未知，也没有正常的取消按钮。界面的帮助和设置仍只讲手动元宝 Cookie，与现有代理代码不一致。建议清楚说明需要已登录的 PC 微信、播放步骤和代理状态，支持取消并展示恢复结果。
5. **视频号下载完成校验不足。** `app/wechat.py:214` 仅检查 FFprobe 能否识别视频流，不能证明视频完整、音频存在、时长正确或作品身份匹配；部分文件先改成最终文件名，再校验。建议先在临时文件完成大小、时长、流和身份校验，再原子发布；将无音轨与缺少预期音轨区分。

## 作品覆盖与验收缺口

现有 [平台覆盖实测报告](../平台覆盖实测报告.md) 前文如实记录了样本和限制，但末尾把少量样本称为“100%支持”，并把视频号“已实现部署”与实测通过放在同一矩阵中。此前总结中“全部平台 100% 跑通”也没有足够依据。建议维护按作品类型、样本、日期、是否登录、下载文件与校验方法组成的矩阵，明确区分已实测、代码支持但未验证、不支持和失败。

- 快手竖向长图目前保存切片，尚未还原原始完整图片；快手实况样本虽然文案写 live，服务端实际只返回静态图，不能证明动态实况已支持。
- B站专栏和 Opus 图文明确不支持；番剧、影视、直播回放、付费或受权限限制的内容以及复杂合集没有充分验收。
- 抖音短剧、长片、合集，以及精选的更多类型尚无充分实测。匿名访问、平台风控和画质因作品而异。
- 小红书视频与实况已有有限成功样本，不能由此保证全部混合图文、动态资源或所有分享链接均可用。
- 视频号代理捕获存在代码路径，但现有记录未提供该方案的真实客户端成功下载及作品身份匹配证据；图集、直播等也未验证。所谓免手动 Cookie 仍需要已登录的微信客户端。

## 功能与体验

1. 首页仅提供一个输入框和“解析并下载”，缺少作品预览、画质选择和下载前选择分P/图片；应先明确最小范围，再逐步增加。
2. 任务页有取消、失败重试、打开文件夹；缺少暂停/继续、批量管理和历史记录清理等入口。建议优先补充可靠取消、失败原因和恢复，再考虑批量操作。
3. 目录和文件名包含完整标题、作品 ID，图文目录内文件又重复长标题；建议在保持平台/作者/作品归档下缩短子文件名，例如 `001.webp`、`001.mp4`，并确保重名与历史路径兼容。
4. 首页显示“优先可用画质”，但用户无法选择或直观看到最终分辨率、音轨、图片数量和是否存在缺失动态资源。建议在任务详情明确展示实际结果，而非承诺原画或无水印。
5. 字幕提取、语音转写目前明确不包含在产品中；属于用户此前暂缓的后续处理，不应宣称已有。
6. 视频号元宝 Cookie 以明文文件保存（`app/wechat.py:334`）；建议采用 Windows 凭据保护并提供清除、失效提示，避免日志和错误泄露凭据。

## 工程和维护

- `app/downloader.py` 约 7,485 行、`app/task_manager.py` 约 3,705 行，平台逻辑和任务逻辑较集中，修改容易波及其他平台。建议先按平台和公共传输边界渐进拆分，保留现有回归测试。
- 部分能力依赖 yt-dlp、Playwright、Chrome、FFmpeg/FFprobe 和平台返回结构。建议增加启动环境自检、依赖版本显示、平台定期小样本冒烟及失效提示；自动化测试通过不等同真实平台可用。
- 视频号单独维护任务状态及持久化，和主任务队列存在不同状态与行为；建议统一任务模型和状态协议，避免界面遗漏和重试行为不一致。

## 建议顺序

先修复视频号作品匹配、代理恢复和状态显示，再用真实客户端完成单作品、取消、失败、异常退出和并发验收；然后修正覆盖声明并补齐高频作品样本；之后改善目录命名、任务信息和操作；最后按实际使用情况增加批量、画质选择等能力。
